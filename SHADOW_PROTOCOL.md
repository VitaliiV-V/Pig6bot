# Анонимные публикации

Данные новой функции хранятся в `shadow.json` в корне проекта. Бот создаёт файл
автоматически и перечитывает его при запросах; после ручной выдачи или продления
подписки перезапуск не нужен. Пример структуры без пользовательских данных:
[`shadow.json.example`](shadow.json.example).

## Подключение Telegram

1. Обновите зависимости: `pip install -r requirements.txt`. Для сообщений
   каналам и цветных кнопок требуется `python-telegram-bot` версии 22.7 или новее.
2. В основном канале бот должен быть администратором с правом удаления сообщений.
   Включите подписи авторов, как для существующей защиты каналов: бот проверяет
   название отправляющего канала с невидимым UUID в подписи.
3. Добавьте этого же основного бота администратором в магазины
   `@pig6storeplus`, `@pig6store_pro_x5`, `@pig6store_pro_x20`.
   Включите сообщения каналам и предоставьте боту право управлять этими
   сообщениями (`can_manage_direct_messages`).
4. Пользователь создаёт свой канал, оставляет в администраторах только владельца
   и бота, даёт боту право менять информацию канала и публикует `Shadow`.
   Бот автоматически регистрирует владельца и устанавливает название только
   из невидимых символов Unicode (`U+E0100`–`U+E01EF`), без букв, цифр и пробелов.
   Название состоит из невидимого идентификатора канала и невидимого UUID.
   После каждого нового анонимного поста в основном канале UUID меняется.
   Ранее зарегистрированные Shadow-каналы автоматически получают невидимое
   название при запуске бота; архив авторства и подписки сохраняются.

Владелец должен сначала открыть личную переписку с ботом, чтобы получать
уведомления об исчерпании лимита или проблемах с защитой. Повторная публикация
`Shadow` восстанавливает защиту, если бот потерял права или название изменили вручную.
Канал с уже подключённой обычной защитой сначала нужно отключить через `unprotect`.

Сообщения магазину приходят в отдельную тему переписки. Бот проверяет родительский
канал и отправителя и отвечает в ту же тему. Ответ администратора магазина,
сообщение в другом канале и повторная доставка того же обновления не дают
дополнительный месяц. Используемые поля описаны в
[Telegram Bot API](https://core.telegram.org/bots/api#directmessagestopic).

## Подписки и лимиты

| Тариф | Анонимные посты в день | Просмотры авторства в день |
| --- | ---: | ---: |
| Free | 1 | 0 |
| Plus | 5 | 0 |
| Pro x5 | 25 | 1 |
| Pro x20 | 100 | 5 |
| Ultra | 1000 | 100 |

`/sub` в личной переписке показывает текущий тариф, срок действия, остатки
обоих лимитов, время до сброса и кнопку «Изменить подписку». Под каждым лимитом
показана полоса из двадцати символов: `▓` — доступный остаток, `░` — потраченная
часть. При нулевом лимите полоса пустая: `░░░░░░░░░░░░░░░░░░░░`.

«Изменить подписку» открывает лицензионные условия: пользователь подтверждает
статус администратора, получает ограниченное право использования функций
и принимает политику безопасности. За нарушение правил оплаченная подписка
может быть отозвана, права администратора сняты, а пользователь удалён или
заблокирован в канале. Посты могут удаляться без уведомления. Добровольные
возвраты не предусмотрены; обязательные требования закона сохраняются.
После «Подтверждаю и принимаю» появляются тарифы и кнопки трёх магазинов.
Это заявление пользователя о статусе администратора, а не проверка его прав
через Telegram API.

В записи подписки сохраняются `terms_accepted_at`, `terms_version`,
`administrator_confirmed_at`, `security_policy_url` и `security_policy_sha256`.
Последнее поле фиксирует SHA-256 текста статьи на момент принятия условий.
Принятие условий не меняет тариф и не расходует лимиты.
Кнопка «К подписке» возвращает текущие остатки.
Смена подписки и выбор тарифа выделены синим, принятие условий — зелёным.
Возврат и ссылка на политику используют стандартный цвет Telegram.
Старые клиенты Telegram отображают кнопки без цветового оформления.

Тексты анонимных публикаций и подписок используют единый спокойный стиль:
короткие заголовки, ясные действия и минимум декоративных элементов.
Лицензионные условия и политика безопасности оформлены как формальные документы.

## Статья с политикой безопасности

Адрес страницы формируется из `WEB_SITE` в `.env` с добавлением `/security-policy`.
Например, `WEB_SITE=http://127.0.0.1:2322` даёт
`http://127.0.0.1:2322/security-policy`, а `WEB_SITE=https://pig6bot.sos.al`
даёт `https://pig6bot.sos.al/security-policy`. Завершающий слеш в `WEB_SITE`
не создаёт двойной слеш. Если переменная не задана, используется локальный
адрес `http://127.0.0.1:2322`. После изменения `.env` перезапустите бота и сервер.
Ссылка присутствует в тексте лицензионных условий, в отдельной кнопке и в
навигации сайта; адрес в самой статье также учитывает `WEB_SITE`.
Маршрут подключён к существующему FastAPI-серверу; на публичном домене он
появится после обновления и перезапуска сервера этой версией проекта.

Редактируйте только `web/security-policy.txt`: это обычный текст в UTF-8,
HTML писать не нужно. Уже подготовлена стандартная политика с нумерованными
разделами о полномочиях, запрещённых действиях, публикациях, раскрытии автора,
подписках, санкциях, платежах, учёте данных и обращениях к администрации.
Страница перечитывает текст при каждом запросе, сохраняет абзацы и переносы
строк и экранирует HTML. Изменения текста не требуют перезапуска приложения.

Каждое новое сообщение пользователя соответствующему магазину активирует
подписку на один календарный месяц. Тот же активный тариф продлевается на месяц
от текущего срока окончания. При смене тарифа новый включается сразу на месяц
от момента обращения. Например, Plus до 7 ноября продлевается до 7 декабря;
переход на Pro x5 7 октября включает Pro x5 до 7 ноября. При переходе остаток
предыдущего тарифа не переносится. В конце месяца число ограничивается последним
днём следующего месяца: 31 января → 28/29 февраля.

При первом сообщении боту (включая `/start` и `/sub`) или регистрации Shadow-канала
новый пользователь автоматически получает Plus бесплатно на один календарный
месяц: 5 анонимных постов в день и 0 просмотров авторства (или вручную заданные
лимиты Plus из `plans`). Новым считается пользователь без записи в `subscriptions`.
Существующие записи, включая Free, сохраняются. В `/sub` отображаются бесплатный
период и дата окончания. После окончания действует бессрочный Free.

В JSON сохраняются `trial_started_at` и `trial_expires_at`. Повторный `/start`,
запрос `/sub`, регистрация другого канала и перезапуск бота не выдают бонус заново.
Сохраняйте запись пользователя и эти поля при ручном редактировании; удаление
записи сделает его новым пользователем. Покупка Plus во время бесплатного месяца
продлевает срок на ещё один месяц, покупка другого тарифа включает его сразу.

Истёкшая подписка автоматически считается Free. Смена тарифа и повторная
регистрация канала не обнуляют потраченные за день лимиты. Лимиты общие для
всех Shadow-каналов одного владельца и сбрасываются в 00:00 по Москве.
Альбом считается одной публикацией, редактирование уже принятого поста
повторно лимит не расходует. Пост сверх лимита удаляется.

Чтобы посмотреть автора, отправьте боту ссылку на Shadow-пост основного канала:
`https://t.me/channel/123` или `https://t.me/c/1234567890/123`.
Бот показывает «Автор», имя и username (если есть) владельца на момент публикации.
Остатки лимитов показываются только в `/sub`.
Telegram ID отдельной строкой не показывается.
Название и ссылка Shadow-канала в ответе не показываются. Повторный просмотр
того же поста тем же пользователем бесплатный, в том числе после сброса лимитов.
Неизвестные посты и ссылки на другие каналы просмотры не расходуют.
У старых публикаций, созданных до подключения анонимных публикаций, авторство не сохранено.

## Ручная выдача и продление

В `shadow.json` раздел `subscriptions` содержит подписки по **Telegram user ID**.
Добавьте или измените запись, например:

```json
"subscriptions": {
    "123456789": {
        "plan": "Ultra",
        "expires_at": "2026-11-07T00:00:00+03:00"
    }
}
```

Используйте названия `Free`, `Plus`, `Pro x5`, `Pro x20`, `Ultra`.
Для продления поменяйте `expires_at` на нужную дату. Время рекомендуется
указывать с `+03:00`; время без часового пояса трактуется как московское.
`expires_at: null` означает бессрочную ручную подписку.
Если в существующей записи есть `revealed_posts`, сохраните этот список,
чтобы уже раскрытые публикации продолжали показываться бесплатно.

В разделе `plans` вручную меняются `posts_per_day` и `views_per_day` для каждого
тарифа; значения — целые неотрицательные числа. `stores` сопоставляет username
магазина (без `@`) с тарифом. В `usage` можно увидеть текущие суточные счётчики.
Разделы `channels`, `posts` и `purchases` содержат состояние защиты, архив авторства
и сведения об уже обработанных сообщениях магазину.

Для ручного редактирования во время работы сохраняйте файл атомарно и используйте
блокировку `shadow.json.lock`; обычный безопасный вариант — остановить основной бот
на время редактирования. Бот сам пишет через временный файл и атомарную замену,
ошибочный JSON не заменяет пустыми данными. Файл содержит сведения об авторах и
подписках и исключён из Git вместе с файлом блокировки.

## Проверка

```bash
python -m unittest discover -s tests -v
```

Тесты используют временные JSON-файлы и имитацию Telegram API. Они не запускают
ботов, не изменяют рабочую конфигурацию и не обращаются к базе экономики.
